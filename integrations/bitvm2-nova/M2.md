# M2: fixed-claim multiplication and complete Pasta point traces

This extends PR #17 at `1b61d9aaae4f6119a726d13214d74e6c46028eed`.
The new Python compiler reuses M1's arithmetic kernels without modifying them.
The header prover, its `k`, and BitVM3 are unchanged. This package runs no
Nova proving jobs and sends no Bitcoin transactions.

## Implemented

`trace.py` constructs a typed, verifier-owned arithmetic graph and commits a
complete admitted assignment. A named wire has the same SHA-256 opening hash
at every use. The program digest includes the field role (base and scalar
roles stay distinct), operation ID, context, full wire layout, constraints,
and their order. Each leaf includes that digest, the claim digest, its ordinal,
and predicate direction. `require_identity` checks caller-owned expectations.
Consumers must authenticate the expected identifiers independently.

A multiplication has 274 constraints: nine multiplier-limb reconstructions,
nine initial-zero word checks, 255 linked Horner transitions and a final field
equality. Bits reconstruct the actual multiplier in Script. State wires connect
adjacent steps. A consistent computation using the wrong multiplier is therefore
refutable even when every individual Horner equation is true.

`curve_trace.py` emits a 3,616-constraint graph for addition on either Pallas
or Vesta. The graph includes all branches for every assignment. A claimed
dispatch cannot change the graph topology. It covers both identities, doubling,
inverse cancellation and ordinary addition. Input/output membership in
`y^2 = x^3 + 5` is checked, infinity requires zero coordinates, and active slope
denominators are nonzero. Curve products use 13 fully expanded multiplication
traces. Disproofs cover canonical off-curve points and false branch claims.

The slope equations are `(x2-x1)*lambda = y2-y1` for ordinary addition and
`2*y1*lambda = 3*x1^2` for doubling. Both finite paths enforce
`lambda^2 = x1+x2+x3` and `lambda*(x1-x3) = y1+y3`.

## Evidence and limits

Local Python execution passed 24 new tests, including every leaf of one full
point-addition graph on each curve. Tests alter every multiplier bit and every
intermediate multiplication accumulator. Other cases cover wrong final values,
changed openings, swapped contexts, graph changes and malformed input rejection.
`results/m2-local-evidence.json` records the measured scope.

| Operation, either curve/field | Leaves | Sum of disproof script bytes | Largest leaf | Peak reference stack |
| --- | ---: | ---: | ---: | ---: |
| Field multiplication | 274 | 1,267,065 | 4,900 | 215 |
| Complete point addition | 3,616 | 16,540,432 | 4,900 | 215 |

These are exact compiled fixed-claim script sizes. Aggregate bytes count every
leaf once. They exclude transaction framing, WOTS assertions, control blocks and
presigned transactions. They are not fee estimates. The current bit-serial
implementation is a correctness baseline with a large aggregate footprint.
Optimize multiplication and reused point-validation work before projecting a
full IPA MSM or bridge cost.

`bench_m2.py` streams 10,884 Script fixtures to JSONL and creates 74 independent
curve-oracle cases. The local generation process peaked at 160,784,384 bytes RSS
on the recorded host. This measures fixture construction, not a prover or full
Nova verifier, and is not an OS-enforced RAM ceiling. One complete fixed-claim
assignment is retained in memory; only scripts/fixture output are streamed.

`m2-oracle` uses halo2curves `=0.9.0` to check curve vectors. It also executes the
Script vectors in BitVM's interpreter at
`ba96bc2bd76774c9d1b011461cb79d983c2c43a1`, with actual initial-stack witnesses,
minimal encodings and the 1,000-item stack limit. Experimental OP_CAT is explicitly
disabled, and an opcode allowlist independently rejects unsupported instructions.
The upstream Tapscript opcode counter is unavailable; the JSON result reports
null and preserves a separate reference-instruction count.

Rust compilation and execution were unavailable locally. Read the M2 GitHub
Actions result and its evidence artifact for the independent outcomes. The
workflow records Cargo.lock and the dependency tree. Its transitive crate
versions are resolved per run; a reviewed committed lockfile is still needed
for a release build.

## Conditional correctness argument

For an admitted assignment with all multiplication predicates true, the
reconstructed bits equal the multiplier. Starting at zero, induction over the
255 transitions gives the product modulo the selected field. Every occurrence
of an intermediate uses the same committed word. Final equality connects that
product to the caller's result wire.

For a point graph whose constraints all hold, the points satisfy the curve and
infinity rules. The constrained dispatch selects exactly one addition case.
The active slope equation has a nonzero denominator, giving a unique slope;
the coordinate equations then give the group-law result. The identity and
inverse paths constrain the output directly. Thus a false result in this
admitted fixed program forces some predicate to be false. Its leaf accepts a
disproof with the committed openings. Conversely, hash binding prevents changing
an opening to refute a true predicate, subject to SHA-256 security.

This argument concerns the emitted fixed-claim graph. It has not been formally
verified or security-audited. The Python reference and independent interpreter
checks cover tests rather than every possible input.

## Production boundary

The claim is known when its per-word hash checks are compiled. This is still a
fixed-claim fixture mechanism. Bitcoin's dynamic BitVM2 assertion commitments,
authenticated transaction graph and Taproot inclusion are unimplemented here.
An arbitrary supplied program must never be accepted on its own declared digest.

Admission happens before commitment: the API accepts bounded integer values and
serializes minimal ScriptNums itself. It rejects noncanonical field values,
malformed types and incomplete assignments. A production adapter must either
force such encodings through its assertion mechanism or provide complete
disproof paths for malformed assertions. Native admission is not an on-chain
malformed-state disproof. The oracle executes scripts without Bitcoin Core
regtest transactions, mempool policy, fees or signatures.

The real NHT4 decoder, exact Nova Fiat-Shamir transcript, Spartan checks and full
IPA verifier remain pending. No complete Nova proof is verified by M2. The
intended pipeline stays Nova/Pallas-Vesta -> Spartan/IPA without Groth16 or KZG.

## Reproduce

```sh
cd integrations/bitvm2-nova
python -m unittest discover -s tests -v
python bench_m2.py
cargo generate-lockfile --manifest-path m2-oracle/Cargo.toml
cargo run --locked --manifest-path m2-oracle/Cargo.toml -- --curves results/m2-curve-vectors.json
cargo run --locked --manifest-path m2-oracle/Cargo.toml -- --scripts results/m2-engine-vectors.jsonl
```
